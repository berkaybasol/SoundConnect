# Listener table profile publications

Table sharing follows the existing listener publication flow: an optional note of at most 500 Unicode code points, immutable publication identity, exact-ID removal, and independent publication engagement. An active card reads the current public table metadata; when the table ends, its last public state becomes an immutable snapshot. Sharing does not create another table, join request or conversation.

Only an active, verified account whose sole personal role and actual profile are LISTENER may publish. Its listener visibility choice must be complete and STANDARD. The source must be ACTIVE and unexpired, and the publisher must currently own it or have an ACCEPTED participant row. PENDING, REJECTED, KICKED, LEFT and missing membership never authorize sharing. Membership/lifecycle checks run after the table aggregate lock, so concurrent cancellation, expiry, removal and leaving cannot publish an unauthorized table.

Authenticated routes (all responses use `Cache-Control: private, no-store`):

| Route | Contract |
| --- | --- |
| `GET /api/v1/table-groups/{tableGroupId}/profile-share` | Own publication state; does not publish. |
| `PUT /api/v1/table-groups/{tableGroupId}/profile-share` | Body `{}` or `{ "note": "optional text" }`; unknown fields, duplicate fields and nontext notes are rejected. |
| `DELETE /api/v1/table-groups/profile-shares/{shareId}` | Removes only the caller's exact publication, preserving the table and membership. |
| `GET /api/v1/public/listener-profiles/{profileId}/table-group-posts?page=0&size=20` | Deterministic publication order: `published_at DESC, id DESC`; page 0–1000, size 1–50. |
| `GET /api/v1/public/listener-profiles/{profileId}/table-group-posts/lookup?shareIds={id1},{id2}` | Refresh 1–50 distinct, nonzero publication IDs. The existing success envelope contains a plain list of the same Post objects. Only requested IDs belonging to this profile are returned; deleted/unreadable IDs are omitted. |

State fields: `tableGroupId`, `shareId`, `publishedOnProfile`, `note`, `publishedAt`, `canPublish`, `tableGroup`. An existing publication remains addressable for deletion after membership is lost, closure, expiry or a ghost transition. `canPublish` becomes false when the source is no longer eligible. An archived eligible publication retains its final `tableGroup`; unavailable membership without an eligible final snapshot returns null. A same-note PUT on an eligible active source is an idempotent retry; a different note returns 409. Remove and republish to change the note while the table is open; a delayed DELETE of the former ID cannot remove the replacement. Ended tables cannot receive new publications.

Public post fields: `shareId`, `note`, `publishedAt`, `tableGroup`, `likeCount`, `commentCount`, `likedByMe`. The minimal `tableGroup` card contains `id`, `description`, `venueName`, `cityName`, `districtName`, `meetingAt`, `expiresAt`, `status`, `maxPersonCount`, `acceptedCount`. It never includes identities of participants or applicants, application notes, chat/game content, age/gender preferences, or internal owner metadata. Source cards and engagement counts are fetched in batches.

Active `acceptedCount` is calculated from accepted participant rows on every read, including the owner. Approval changes 1/4 to 2/4; pending applications do not consume seats. The bounded lookup supports refreshing visible cards without fetching or reordering the entire profile timeline.

Natural expiry is 24 hours after creation, independent of the chosen meeting time. A publication whose author still owns or participates in the table at its end remains in the profile with the same ID, date, note and engagement. Natural expiry uses `status=INACTIVE` (display “Bu masanın süresi doldu”); manual/automatic early closure uses `CANCELLED` (display “Bu masa kapatıldı”). The archived source preserves final description, venue/location, meeting/expiry times, capacity and accepted count. Source navigation/join/chat actions should be unavailable on an ended card; profile likes, comments, replies and own publication removal remain available.

The final snapshot and eligibility decision are frozen once under the table aggregate lock, including a frozen-null decision for departed/kicked publishers. A later membership change, participant retention or account erasure cannot change the historical count or resurrect an ineligible share. Before the table ends, lost membership still hides the publication; rejoining while it is active may make the retained publication visible again. Ghost profiles still produce an empty page/lookup, and pending visibility or invalid/inactive target accounts remain profile-not-found. Snapshotting never overrides current author account, role or listener visibility checks.

Lifecycle triggers freeze public state before table closure or an expired participant row changes, including Hibernate collection replacement and account erasure. Profile/state/engagement reads lazily freeze expired tables so visibility does not depend on the scheduler's minute-long scan interval. List/lookup use one request cutoff for live/ended classification, and lookup finalization is limited to the requested sources. Publication reads serialize aggregate finalization; existing 503 retry behavior applies to transaction conflicts.

Likes, comments, replies and comment likes use existing engagement APIs with `TABLE_GROUP_POST` and `targetId=shareId`. Their access guard applies the same source predicate and locks account → listener visibility → table → publication. Other users' publications of the same table remain independent. Source/profile/account cascades and explicit publication removal purge the exact publication's comments and likes transactionally.

Deploy `scripts/db/2026-09-10-tablegroup-profile-shares.sql` after `2026-09-10-listener-account-erasure.sql`, followed by `scripts/db/2026-09-10-tablegroup-profile-share-history.sql`, before the matching backend. Both scripts are additive and rerunnable. The history migration adds `final_source` and `final_source_frozen`, installs lifecycle/immutability triggers, validates the public snapshot field whitelist and backfills existing ended shares from retained source state. Information already removed before deployment cannot be reconstructed; reruns never rewrite a frozen snapshot. Existing source/profile/account cascades and owner-account erasure still remove their shares and engagement. Hibernate schema updates alone do not install these invariants. `scripts/dev.ps1` includes the migrations in order. No database reset is required.

Errors: 9129 publication already exists (409), 9130 invalid input (400), 9131 exact publication missing (404), 9132 storage/transaction unavailable (503, Retry-After 5), 9133 current table membership/lifecycle forbids publication (403). Existing unauthorized, profile-not-found and listener access errors retain their normal codes.

Verification uses disposable PostgreSQL and HTTP contract tests: owner/accepted publication, every terminal membership status, pending/ghost/corrupt role access, expiry before scheduler and before pagination, current accepted counts, bounded scoped lookup, immutable final state, frozen negative eligibility, Hibernate closure/collection cleanup ordering, retained engagement, note Unicode validation, exact deletion/republication, concurrent retries, membership removal during the source-lock wait, migration reruns, source cascades, and listener erasure of peer publications on retained tables.
